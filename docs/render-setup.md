# Render Free Preview Setup

Use Render Free for testing and keep Supabase as the database. The configuration
does not create a database, disk, worker, cron job, or paid service. Adding these
files does not deploy anything.

## 1. Workspace And Repository

In your Render workspace, choose **New > Web Service** and connect GitHub.
Grant access to `justinspratt07/made-for-them`, then select that repository.
**Stop before clicking Create Web Service.**

PR #1 must be reviewed, merged, and checked before deploying `main`. The current
deployment code is on `codex/public-deployment-readiness`; the existing `main`
branch does not have the Render startup scripts yet.

## 3. Service Settings

The repository's `render.yaml` defines one service:

| Setting | Value |
| --- | --- |
| Name | `made-for-them-preview` |
| Runtime | Node |
| Compute plan | Free |
| Region | Virginia, near the existing North Virginia Supabase project |
| Branch | `main`, after the reviewed PR is merged |
| Build command | `pnpm build:render` |
| Start command | `pnpm start:render` |
| Health check | `/api/health` |
| Automatic deployment | Off |
| Node version | `24.21.0` |

Render starts its first deployment when you create a service, even when automatic
deployments are off. Use manual deployments during testing.

The build command installs locked dependencies, including build/preflight tools,
and compiles a server build. Startup checks private settings and both database
roles before listening on `0.0.0.0` at Render's `PORT`. It never migrates or seeds.

## 4. Private Settings

Set these individually in Render's environment settings. **Do not upload the
entire `.env.local` file** or paste its values into chat.

| Variable | Value Source |
| --- | --- |
| `DATABASE_URL` | Supabase reader role, TLS enabled |
| `ADMIN_DATABASE_URL` | Supabase editor role, same endpoint/database, TLS enabled |
| `ADMIN_PASSWORD_HASH` | Private owner password setup |
| `ADMIN_SESSION_SECRET` | New secret generated by the Blueprint, or independently generated with at least 32 characters |

Do not provide `MIGRATION_DATABASE_URL` to Render. Never prefix credentials with
`NEXT_PUBLIC_`. Keep maintenance separate from the web service.

The Blueprint sets `GIFT_DATA_SOURCE=postgres`, `APP_DEPLOYMENT=preview`,
`NODE_ENV=production`, and `ADMIN_CLIENT_IP_HEADER=cf-connecting-ip`; static-export
switches are disabled. Preview mode still requires restricted roles and remote TLS.

Startup derives the exact owner origin from Render's `RENDER_EXTERNAL_URL`.
For a custom domain, set `ADMIN_ORIGIN` to that exact HTTPS origin, without a
trailing slash, and redeploy.

## 5. Actual Host Verification

CI can exercise the Render build/start wrappers and supplied headers against
isolated PostgreSQL. It does not prove Render's real edge behavior.

- [ ] HTTPS opens the expected quiz and all project photos.
- [ ] `/api/health` returns ready without exposing configuration.
- [ ] Signed-out requests cannot read owner records or save changes.
- [ ] Sign-in, draft privacy, publishing, stale-save rejection, and sign-out work.
- [ ] Spoofed `X-Real-IP` and `X-Forwarded-For` cannot change login allowances.
- [ ] Caller-supplied `CF-Connecting-IP` is overwritten at Render's edge.
- [ ] A second genuine network identity has an independent login allowance.
- [ ] No backend port is reachable outside the Render ingress.
- [ ] Restarts preserve gift data and PostgreSQL login counters.
- [ ] Check memory, error logs, and behavior after a free-instance cold start.

Use only the approved testing service for hostile-header checks. Exhausting an
IP's allowance can also block your own sign-in from that IP for 15 minutes;
restarts do not clear the database counter. Do not log raw passwords, cookies,
connection URLs, or visitor IPs.

Render's [PocketBase guidance](https://render.com/articles/host-pocketbase-on-render)
documents `CF-Connecting-IP` as overwritten by its edge. On Render, the app reads
only that single address, not caller-supplied forwarding chains.

## 6. Upgrade And Rollback

Use Free for development and a small beta. Before promoting the production app,
change the web service's compute plan to a suitable paid instance and set
`APP_DEPLOYMENT=production`. Workspace billing and service compute are separate.
Check current prices before upgrading and configure usage notifications.

Free instances can sleep after 15 idle minutes and take about a minute to wake.
Monthly usage limits and unusually high external-database traffic can also cause
suspension. No Render database is needed. [Free limitations](https://render.com/docs/free)

If authentication or permission checks fail, disable owner access and roll back
to the last verified server deploy, or keep using the static GitHub Pages preview.
Do not drop gift data or undo role policies automatically.

Reference: [Next.js deployment](https://render.com/docs/deploy-nextjs-app),
[Blueprint specification](https://render.com/docs/blueprint-spec), and
[platform environment variables](https://render.com/docs/environment-variables).
